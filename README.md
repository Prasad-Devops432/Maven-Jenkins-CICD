# Maven Jenkins CI/CD Demo

A small Java application built with Maven, tested with JUnit, and packaged into
a Docker image by a Jenkins pipeline. The image is pushed to Docker Hub.

> **Source note:** The application and pipeline follow a tutorial by Shubham Gour
> (YouTube: shubhamgourtech). This repository is my practice copy of that pipeline.

## Project structure

```
.
├── src/
│   ├── main/java/com/example/demo/Application.java
│   └── test/java/com/example/demo/ApplicationTests.java
├── pom.xml          # Maven build (produces demo-1.0-SNAPSHOT.jar)
├── Dockerfile       # Runs the packaged JAR on Java 17
├── Jenkinsfile      # Pipeline: clean, compile, test, package, build image, push
└── .gitignore
```

## Run locally

Requirements: JDK 17, Maven 3.9.

```bash
mvn clean test          # run the unit tests
mvn package             # build target/demo-1.0-SNAPSHOT.jar
java -jar target/demo-1.0-SNAPSHOT.jar
```

## Build and run the Docker image

The Dockerfile copies the JAR from `target/`, so build it first:

```bash
mvn clean package -DskipTests
docker build -t maven-jenkins-demo:local .
docker run --rm maven-jenkins-demo:local
```

## Jenkins pipeline

The `Jenkinsfile` runs these stages:

1. **Checkout:** gets the code from source control.
2. **Clean workspace:** runs `mvn clean`.
3. **Build:** runs `mvn compile`.
4. **Unit tests:** runs `mvn test` and publishes JUnit results.
5. **Package:** builds the JAR and archives it as a build artifact.
6. **Docker build and push:** builds the image and pushes it to Docker Hub, tagged with the build number.

Jenkins needs a `DockerHub` credential, and the image name in `Jenkinsfile`
(`IMAGE_NAME`) must point to a Docker Hub repository you can push to.

## Notes

- The `target/` folder is generated by the build and is excluded in `.gitignore`.
- The test in `ApplicationTests.java` is a plain JUnit 4 test that checks the `greet()` method. It does not start a web server.
